Project 01 · Version 02

V2 — Autonomous Pick & Place

STRYKER V2

A fully autonomous pick-and-place system built on the V1 platform — integrating a computer vision pipeline, geometric inverse kinematics, custom PCB, and empirical servo calibration to detect and retrieve a red block from a live camera feed.

DOF

6 (J1 yaw, J2–J3 pitch, J4–J5 wrist, J6 gripper)

Controller

Arduino Nano + PCA9685 PWM driver

Vision

iPhone overhead + ArUco fiducials

Software

Python / OpenCV pipeline

Calibration

RANSAC homography + piecewise-linear servo model

Outcome

Autonomous red block detection & pick-up

System Architecture

  • Three independently testable subsystems: mechanical arm, computer vision pipeline, and software control stack
  • Pre-design physics simulator evaluated arm configurations, center-of-mass footprint, and tipping risk before fabricating — flagged extended configs as "POSSIBLE TIPPING," directly informing base reinforcement
  • Modular Python codebase: separate modules for camera capture, detection, kinematics, Arduino communication, and pick-and-place state machine

Computer Vision Pipeline

  • iPhone mounted overhead on frame — full workspace visible, minimal perspective distortion
  • Four ArUco fiducial markers (IDs 0–3) at workspace corners; RANSAC-based homography maps pixel coordinates to real-world XY in the arm base frame
  • Each frame converted to HSV; red block isolated via dual-mask thresholding + minimum saturation gate to reject lighting-induced noise
  • Confidence score filters false positives (faces, hands, circular objects); accepted centroid forwarded to IK solver

Custom PCB & Electronics

  • Custom PCB integrates Arduino Nano with PCA9685 16-channel PWM servo driver — routes all six servo signal lines and power on a single board
  • JST connectors on servo leads for tool-free disassembly; eliminated intermittent failures that plagued breadboard prototype
  • Compact footprint designed to embed in arm base in future iterations

Inverse Kinematics & Servo Calibration

  • Three-step geometric IK: (1) base yaw q₁ = atan2(y, x), (2) 2R cosine-law solve for q₂ and q₃ with both elbow branches evaluated, (3) wrist pitch q₅ searched over 180°–136°
  • Piecewise-linear servo characterization with asymmetric slopes per joint — captures real servo behavior significantly better than a single linear fit
  • Empirical correction via custom STRYKER Manual Joint Control UI: arm manually driven to five target positions; joint pulse values and vision-measured XY coordinates recorded and fit to correction model

Autonomous Pick Sequence

  • Eight-command sequence: Approach → Descend → Grasp → Lift → Approach → Descend → Release → Lift
  • Smoothstep motion interpolation at 9–700 ms per move — tuned to minimize joint jitter without excessive cycle time
  • Successfully demonstrated autonomous red block detection and pick-up in live testing (ROB 310 final demo)

Challenges & Next Steps

  • HSV thresholding sensitive to variable lighting — required multiple threshold and morphological parameter iterations to achieve robust detection
  • IK solver evaluates only two elbow branches; workspace-boundary edge cases occasionally produced unreachable configurations
  • Place-down sequence not completed within project timeline — primary target for next iteration
  • Future: continuous vision loop, low-pass filter on servo PWM, Jacobian-based IK for full reachability

Project 02 — Controls & Mechatronics

SENTINEL

A self-balancing ball robot designed, built, and controlled from scratch — full-stack robotics covering motor selection, kinematics, electronics, and dual PID balance and steering control.

Platform

Basketball + omni wheels

Power

12V battery, 2A motor drivers

Sensing

IMU (gyro + accel), encoders

Control

Dual PID — balance & steering

Comms

Bluetooth controller interface

Outcome

Competition — balance, steer, race

Design & Motor Selection

  • Applied design analysis framework (DAF) to model motor-to-ball dynamics and select motor meeting torque demands without overheating or over-drawing current
  • Selected gearbox and wheel geometry through kinematic modeling; evaluated thermal management for sustained operation
  • Verified motor adequacy under conservative single-wheel loading via inverse modeling

Kinematics & Kinetics

  • Derived motor-to-ball motion relationships using planar and 3D ball-bot kinematic models
  • Applied transmission and linkage analysis to characterize wheel-to-ball force and velocity

Electronics & Communication

  • Integrated IMU for balance feedback, encoders for odometry
  • Bluetooth interface for real-time control input and mid-run IMU re-zeroing
  • UART data logging pipeline for controller tuning and performance analysis

PID Balance & Steering Control

  • Separate PID loops for balance (tilt → wheel torque) and steering (heading → differential drive)
  • Tuned P, I, D gains independently per axis using step-input responses and sensor plots
  • Exponential filtering on IMU data to reduce noise impact on derivative term
  • Validated through live trials — balancing, disturbance rejection, and track steering

Competition

ROB 311 end-of-semester competition — four events: timed balancing, disturbance rejection, steering around a prescribed track, and head-to-head race. Final report documented controller design, sensor plots, odometry, and step-input responses across all control modes.

Project 05 — Embedded Systems

PATHFINDER

An autonomous line-following robot built on a cascaded control architecture — bang-bang lateral guidance feeding a PID wheel-speed controller for precise, stable traversal.

Platform

MBot (differential drive)

Microcontroller

Raspberry Pi Pico (MicroPython)

Line Sensing

7-ch IR reflectance array (I2C)

Feedback

Quadrature encoders, 48:1 gear ratio

Control

Bang-bang → PID cascade

Smoothing

Exponential filter (α ≈ 0.75)

Encoder & Motor Control

  • Interrupt-driven quadrature decoder via MicroPython Pin.irq() — event-driven, no polling
  • Motor class: forward/reverse PWM at 10 kHz, duty-cycle saturation protection
  • Wheel speed calculated in rev/s from tick and time deltas; verified against AD2 oscilloscope

PID Wheel Speed Controller

  • Time-discrete P, I, D terms tuned for step-input response with minimal overshoot
  • Motor current sensed via ADC (1 V/A); logged PWM, speed, setpoint, and current
  • Output saturation applied to prevent integrator wind-up at duty cycle limits

Line Sensor (I2C / PCA9557)

  • Configured PCA9557 I/O expander: set configuration, polarity inversion, and output registers
  • Read() method: enables LED array → reads 7-bit reflectance byte → disables array
  • Polarity inversion ensures bits read HIGH when sensor is over white line

Bang-Bang → PID Cascade

  • Bang-bang reads reflectance array and outputs left/right speed setpoints
  • Exponential smoothing (α ≈ 0.75) reduced in-rush current by ~150 mA vs. unfiltered
  • PID controllers at ~50 ms loop period — demonstrated successful curved-course traversal
